## 5. 验收发现并修复的缺陷

**现象（P1）**：全挂时（有候选但全部失败），网关返回的 `error.message` 为 `"Internal server error (simulated)."` —— 透出了最后一个上游响应体的错误原文。

**根因（跨模块契约脱节）**：
- 服务端 `gateway_service.py` 在 `all_upstreams_failed` 分支用 `last_message`（上游响应体 `error.message` 原文）作为最终 message；
- Android `RouteResult.friendlyError` 原实现信任「网关 message 已是安全文案」，直接透出。

**修复（方案 B，Android 侧）**：`friendlyError` 改为按 `error.type` 映射固定友好文案、HTTP 状态兜底，**完全不展示网关 message**，杜绝任何上游细节泄露路径。配套单测 `typeMapOverridesGatewayMessage` 显式构造含技术细节的 message 验证不透出。

**遗留建议（可选）**：网关侧 `all_upstreams_failed` 的 message 使用脱敏文案会更友好（可看到具体失败原因），属 B 模块优化项，不影响验收。
